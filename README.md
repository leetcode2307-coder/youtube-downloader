# YouTube Downloader — FastAPI + Flutter

A minimal, production-shaped project:

- **Backend (FastAPI)** runs `yt-dlp` in the background, downloads the best
  video+audio, merges them, and saves the finished file straight to a
  `downloads/` folder on disk. Only metadata (filename, size, timestamp) is
  ever stored in SQLite — the video bytes never pass through app memory.
- **Frontend (Flutter)** is a single screen: paste a URL, tap Download,
  watch the status, see a clean history list of completed downloads. The
  video itself is never fetched, streamed, or previewed by the app — it
  fires a local notification (in IST / Asia-Kolkata time) when the job
  finishes or fails.

```
youtube-downloader/
├── backend/
│   ├── main.py            # FastAPI app & endpoints
│   ├── downloader.py       # yt-dlp subprocess runner
│   ├── database.py         # SQLite storage (jobs + completed downloads)
│   ├── requirements.txt
│   └── downloads/          # created automatically — final files land here
└── flutter_app/
    ├── pubspec.yaml
    └── lib/
        ├── main.dart
        ├── models/download_item.dart
        ├── services/api_service.dart
        ├── services/notification_service.dart
        ├── screens/home_screen.dart
        └── widgets/history_card.dart
```

## 1. Backend setup

**Requirements:** Python 3.10+, and `ffmpeg` installed and on your PATH
(yt-dlp needs it to merge separate video+audio streams).

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# make sure ffmpeg is available
ffmpeg -version
```

Run the server:

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

The API is now live at `http://localhost:8000`. Downloaded files land in
`backend/downloads/`.

### Endpoints

| Method | Path              | Purpose                                              |
|--------|-------------------|-------------------------------------------------------|
| POST   | `/download`       | Body `{"url": "..."}` → starts a background job, returns `job_id` |
| GET    | `/status/{job_id}`| Poll job status: `queued` / `downloading` / `completed` / `failed` |
| GET    | `/history`        | List of **only** successfully completed downloads (filename, size_mb, downloaded_at) |

Quick manual test:

```bash
curl -X POST http://localhost:8000/download \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"}'

curl http://localhost:8000/status/<job_id>
curl http://localhost:8000/history
```

Internally the exact yt-dlp command run is:

```bash
yt-dlp -f "bv*+ba/b" --merge-output-format mp4 -o "downloads/%(title)s.%(ext)s" "URL"
```

A file is only added to `/history` **after** yt-dlp exits successfully and
the merged file is confirmed to exist on disk — partial or failed downloads
never appear.

## 2. Flutter setup

The `flutter_app/` folder contains `lib/` and `pubspec.yaml` — the actual
app code. Platform folders (`android/`, `ios/`, etc.) are generated by the
Flutter CLI itself so they always match your installed SDK version.

```bash
cd flutter_app
flutter create . --project-name youtube_downloader   # generates android/ios/etc, keeps lib/
flutter pub get
```

### Point the app at your backend

Open `lib/services/api_service.dart`:

- Android **emulator** → keep the default `http://10.0.2.2:8000` (this is
  the emulator's alias for your host machine's `localhost`).
- iOS **simulator**, **desktop**, or **web** → change it to
  `http://localhost:8000`.
- Physical device → use your computer's LAN IP, e.g. `http://192.168.1.20:8000`,
  and make sure the phone is on the same network.

### Enable notification permissions

**Android** — in `android/app/src/main/AndroidManifest.xml`, inside the
`<manifest>` tag (above `<application>`), add:

```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
```

**iOS** — no extra config needed beyond what `flutter_local_notifications`
already sets up; the app requests permission at launch.

### Run it

```bash
flutter run
```

Make sure the FastAPI backend (step 1) is already running before you tap
Download.

## How it stays "minimal but production-shaped"

- **No video ever touches app memory or the Flutter client.** The backend
  writes straight to disk; the API only ever returns small JSON metadata.
- **Background, non-blocking downloads.** `asyncio.create_subprocess_exec`
  + FastAPI `BackgroundTasks` mean the `/download` call returns instantly
  while yt-dlp keeps working.
- **History is derived, not guessed.** A row is written to SQLite only
  after yt-dlp's own `--print after_move:filepath` confirms the final,
  merged file exists on disk.
- **One screen, one job at a time, no auth, no player.** Exactly the
  surface area the task needs and nothing more.

## Troubleshooting

- **"yt-dlp is not installed or not on PATH"** → `pip install -U yt-dlp`
  inside the backend virtualenv, and confirm `yt-dlp --version` works in
  that same shell.
- **Merge fails / no audio** → install `ffmpeg` and make sure it's on PATH.
- **Flutter can't reach the backend** → double-check the `baseUrl` in
  `api_service.dart` for your specific run target (emulator vs. simulator
  vs. physical device).
- **No notification appears** → confirm notification permission was
  granted (Android 13+ requires it explicitly), and that the app isn't in
  a battery-saver mode that blocks background notifications.
